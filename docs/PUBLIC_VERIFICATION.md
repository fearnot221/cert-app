# 流水號查詢、密碼下載與期限

更新：2026-10-15。QR Code 公開驗證已移除；PDF、模板、活動頁與「我的證書」都不再產生或顯示 QR。

## 使用流程

1. 建立活動時，名單須提供「證書流水號」，與姓名、Email 一樣由匯入或手動填寫。流水號在同一組織內不可重複，系統不再自動編號。
2. 「通知收件人」寄出的信件包含證書流水號、一組下載密碼，以及 `/download?serial=…` 連結。收件人不需註冊或登入，輸入流水號與密碼即可下載 PDF。
3. 任何人都能在首頁或 `/verify/:serial` 輸入流水號，確認它是否由本系統發出及目前狀態。查詢結果不含持有人姓名、Email 或 PDF。
4. 建立活動可設定「證書到期日」，留空為無到期日。日期以 Asia/Taipei 當日 23:59:59.999 為截止點。管理員可「管理期限」，填寫原因後設定、縮短、延長或移除期限。PDF 不會因期限變動而重寫，查詢頁為最新期限來源。

## 流水號規則

- 正規化：NFKC、去除前後空白、英文字母轉大寫。`sta-2026-0001` 與 `STA-2026-0001` 視為同一個流水號。
- 格式：1–64 字元，第一個字必須是文字或數字，其後可用文字、數字與 `- _ . / # ( )`。
- 唯一性：同一組織內，一個流水號只屬於一位收件人（同一列的補發版本可以沿用）。名單內重複、與其他活動或既有證書重複都會在「檢查名單」時標出；建立時伺服器在組織鎖內再檢查一次，資料庫另有 exclusion constraint `Certificate_serial_one_lineage` 作最後保障。
- 補發：預設沿用原流水號與原下載密碼，收件人用原通知信即可下載新版；改成新流水號時舊流水號隨舊版失效，需重新寄送通知。
- 不同組織可以使用相同流水號；公開查詢會分別列出各組織的紀錄。

## 下載密碼

- 每次寄送通知時由 worker 產生 12 碼密碼（`XXXX-XXXX-XXXX`，排除易混淆的 0／O、1／I），SMTP 接受後才把 argon2id 雜湊寫入證書；明文不落地。重寄通知會換成新密碼，舊信中的密碼失效。
- 輸入時不分大小寫，連字號與空白可省略。
- `POST /api/public/certificates/download`（`{ serial, password }`）每 IP 每 10 分鐘 10 次；同一張證書連續錯誤 10 次鎖定 15 分鐘，成功後歸零。錯誤訊息不區分「查無流水號」與「密碼錯誤」。
- 撤銷、到期、被取代或活動取消的證書拒絕下載（410）。成功下載寫入 `certificate.downloaded_with_password` 稽核。
- 尚未寄送通知的證書沒有密碼，無法用這個方式下載。

## 公開查詢

`GET /api/public/serials?serial=…` 不需登入；每 IP 每分鐘 60 次，回應為 `no-store`、noindex。每筆紀錄只回傳組織名稱、活動名稱、發證日期、期限與狀態：

- valid：有效且成功產製，未過期。
- expired：資料庫業務狀態仍為 valid，但目前時間已達期限。
- revoked：撤銷。
- superseded：已被補發版本取代（且新版改用不同流水號）。
- unavailable：組織停用，無法確認有效性。
- 查無或未產製成功：404。

舊的 `/verify/<uuid>` QR 連結會顯示「QR Code 驗證已停用」，請改用流水號查詢。已印出的舊 PDF 上若有 QR，掃描後同樣導向該頁。

## 部署注意

目前 demo 為 `http://localhost:5173`，尚未部署到 Internet。正式寄送前須設定 HTTPS 的 APP_ORIGIN，通知信中的下載連結使用這個網址。目前 production 的 MAIL_MODE 為停用，正式 SMTP 啟用前不會寄出任何密碼。流水號查詢不是 PKI 數位簽章或第三方認證。
